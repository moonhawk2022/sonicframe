## 〇、先说结论

你描述的功能（歌名 + 滚动歌词 + 律动柱 + 背景图 + 比例切换）是**正确的最小核心**，
已按此实现为一个可运行的本地原型。但“能生成视频”和“用户愿意反复用、愿意付费”之间，
还隔着 6 大块：**歌词时间轴、渲染管线、平台适配、合规、新手引导、商业化**。
其中歌词时间轴是用户流失的第一原因，建议最优先投入。

---

## 一、核心流程缺口（P0，不做就没有留存）

### 1. 歌词时间轴是真正的痛点
- ✅ **已完成（低成本方案）**：音乐文件内嵌歌词自动识别——ID3v2 USLT/SYLT（MP3）、
  FLAC VORBIS_COMMENT（LYRICS/UNSYNCEDLYRICS）、M4A ©lyr、RIFF 'id3 ' 块（WAV）。
  网易云/QQ音乐下载的 MP3 大多内嵌歌词（且多为带时间戳的 LRC 文本），能覆盖相当比例的用户；
  带时间戳的内嵌歌词直接进入精确同步，纯文本走自动对齐。
- 🏗️ **无内嵌歌词时的完整方案**：ASR 语音识别 + 强制对齐（Whisper + whisperX / MFA），
  把每个字/词的时间点对出来，实现真正的逐字卡拉 OK。纯浏览器算力与模型体积做不到
  生产级精度，需服务端 GPU 推理（成本约 ¥0.02~0.05/首，可用 GPU 池 + 队列削峰）。
- 🏗️ **可视化打轴界面**：波形图 + 歌词列表，拖动或按回车逐句打点
  （本原型已内置"整体偏移 ±3s"快速校正）。

### 2. 浏览器录制 ≠ 生产级渲染
- ✅ **浏览器端已升级为生产可用水准**：WebCodecs 离线逐帧编码（H.264/AV1 + AAC）+
  自研渐进式 MP4 封装，帧数时间戳精确、切后台不掉帧、恒定码率控体积（≤10MB 可承诺）、
  1080p+AV1 小体积通道。日常单支 MV 场景已可商用。
- 🏗️ **云端渲染（规模化必须）**：音频/图片上传对象存储 → 任务队列 → 服务端 FFmpeg / Remotion
  → MP4 → CDN。带来：4K、逐帧精确可重试、批量任务、模板合成、低配手机也能出 4K。
- 🏗️ 服务端渲染规格建议：H.264 yuv420p + AAC，`ffmpeg loudnorm` 二次响度校准。

### 3. 输出规格要明确
| 项目 | 建议值 |
|---|---|
| 容器/编码 | MP4（H.264 High profile，yuv420p）+ AAC 192kbps |
| 分辨率 | 1080p 起，付费档 2K/4K |
| 帧率 | 30fps（舞蹈/卡点类可 60fps） |
| 响度 | -14 LUFS 统一标准化（平台通用标准） |
| 文件名 | `歌名-MV-16x9-1080p.mp4` |
| 附带产物 | 封面图（视频第 N 帧导出）、字幕文件 .srt（可选） |

## 二、平台适配与视觉规范（P0）

### 4. 竖屏安全区
✅ **已实现**：竖屏歌词横向收窄至 76% 画布宽（避让右侧点赞/评论按钮列）、
律动柱上移至 72% 高度并收窄（避让底部文案区）、品牌角标挪到右上角。
正式产品可把安全区参数做成可配置模板（不同平台数值微调）。

### 5. 排版规则（直接影响“像不像专业做的”）
- ✅ 中文单行 **≤ 14 字**（按标点语义断句，无标点才硬切）；
- ✅ 歌词最小字号下限（渲染端强制 ≥ 0.024×画布宽，约 46px@1920）；对比度由深色遮罩保证；
- 🏗️ 英文/拼音按单词断行，日文按分词断行；双语歌词支持主/副字号分级；
- 🏗️ 长句自动缩字有下限，超过下限改为两行，而不是横向压扁。

### 6. 封面主色提取
✅ **已实现「封面取色」主题**：48×48 缩样 → 12 色相桶加权统计 → 提主色生成
强调色与副色（饱和度/亮度归一到可读区间），歌词填充、律动柱、进度条全部跟随；
黑白灰封面自动拒绝并提示。🏗️ 服务端版本可升级 k-means/中位切分并生成整套装主题。

## 五、音频与渲染技术细节（P1）

- **节拍/段落检测**：能量包络 + onset detection，让律动柱真正“踩点”；
  副歌段落自动加强视觉（放大歌词、加速推镜）；
- ✅ **响度标准化**：解码后按均方根估算 LUFS，统一拉到 -14 LUFS（±12dB 限幅 + 0.98 削波保护），
  预览与导出共用同一条已归一化的音频链路；🏗️ 服务端用 `ffmpeg loudnorm` 做精确 K 加权校准；
- **音画同步**：录制/渲染管线的音轨与视频轨时间戳对齐要验证（原型按实时录制天然同步，服务端逐帧渲染需显式对齐）;
- **帧率稳定性**：WebGL 离屏渲染 + `requestFrame`，或服务端逐帧渲染；
- **大文件**：>50MB 音频分片上传、上传进度与断点续传。

## 七、建议的架构演进路线

```
阶段一（当前原型，已完成 ✅）
  浏览器内：解码（MP3/WAV/M4A/FLAC/OGG）→ 响度归一 → Canvas 渲染
           → WebCodecs 离线逐帧编码（H.264/AV1 + AAC）→ 渐进式 MP4
  已含：内嵌歌词/封面/歌名读取、封面取色、安全区、草稿保存、版权声明

阶段二（上线最小版）
  前端：Next.js + Canvas/WebGL 预览
  后端：对象存储直传 → 任务队列(BullMQ) → Remotion/FFmpeg 渲染 Worker
       → MP4 产出 → CDN
  补齐：账号体系、草稿保存、用量配额、支付

阶段三（专业版）
  ASR 自动打轴（Whisper + 对齐模型）
  节拍检测、主色提取、模板引擎、多语言歌词
  批量任务、API 开放、团队空间
```
